# Phase 7 Plan 01: Expo Mobile Foundation, Navigation Architecture, Cognito Auth & Onboarding Flow

**Phase:** 7 (Mobile Application: Citizen & Collector Modes)  
**Plan:** 01 of 03  
**Requirements:** `AUTH-01`  
**Dependencies:** Phase 5 (Live Backend Deployed), Phase 6 (Shared Domain Contracts)

---

## 1. Goal

Scaffold the Expo React Native mobile application in `apps/mobile`. Establish the navigation hierarchy (Citizen Tab Navigator, Collector Root, and Modal Stacks), type-safe API client pointing to live AWS API Gateway, persistent authentication state with Cognito Email OTP, 1-click Demo Persona Switcher (Aarav - Citizen vs Rajesh - Collector), and complete onboarding flow (Splash, Welcome, Sign In, Verify OTP, Language, Location, and Home Territory Reveal) per `SITEMAP-WEB-AND-MOBILE.md` (B0, B1).

---

## 2. Tasks & Implementation Steps

### Task 1: Mobile Project Scaffolding & Configuration
- Initialize `apps/mobile/package.json` with Expo dependencies:
  - `expo`, `react`, `react-native`, `typescript`
  - `@react-navigation/native`, `@react-navigation/bottom-tabs`, `@react-navigation/native-stack`
  - `react-native-screens`, `react-native-safe-area-context`
  - `@expo/vector-icons`, `expo-status-bar`, `expo-constants`
  - `@saafsafari/shared`, `@saafsafari/game-rules` workspace packages
- Set up `app.json`, `tsconfig.json`, and environment variables referencing live AWS endpoints.

### Task 2: Live API Client & Cognito Authentication Provider
- Build `src/services/api.ts`:
  - Fetch-based HTTP client targeted at `https://dp029jx9uf.execute-api.ap-south-1.amazonaws.com`
  - Automatic Bearer token header injection and error handling for standard API error codes (`OUT_OF_RANGE`, `COOLDOWN_ACTIVE`, `TOKEN_EXPIRED`, `INSUFFICIENT_BALANCE`)
- Build `src/context/AuthContext.tsx`:
  - Cognito Email OTP login flow (`sendOtp`, `verifyOtp`)
  - **Demo Persona Switcher**:
    - **Aarav Sharma (Citizen)**: Ward South 34, 420 GC, Level 4 Van Rakshak, active streak 7 days
    - **Rajesh Kumar (Collector)**: Ward 34 Garbage Truck Driver, assigned rotating QR source `truck-dl1m-4821`
  - Role management (`citizen` vs `collector`) triggering dynamic navigation shell switching
  - Token and persona persistence

### Task 3: Global App Shell & Bottom Tab Navigation (B0)
- Build `src/navigation/RootNavigator.tsx` and `src/navigation/CitizenTabs.tsx`:
  - Bottom Tab bar with 5 tabs: **Home**, **Map**, **Scan** (prominent center action button), **Tasks**, and **Profile**
  - Collector stack when active role is `collector`
  - Permission primer modal screens (`Camera`, `Location`, `Notifications`)
  - Offline status pill and toast notification system

### Task 4: Launch, Sign In & Onboarding Flow (B1)
- Build `src/screens/onboarding/SplashScreen.tsx` (B1.1):
  - Brand splash with animated mascot and token session check
- Build `src/screens/onboarding/WelcomeScreen.tsx` (B1.2):
  - 3 swipeable cards: Do Real Actions, Verify Instantly, Earn Credits & Heal Territoy
- Build `src/screens/onboarding/SignInScreen.tsx` & `VerifyCodeScreen.tsx` (B1.3, B1.4):
  - Email input, Send code, 6-digit OTP verification with countdown timer, Demo 1-tap login buttons
- Build `src/screens/onboarding/LanguageScreen.tsx` & `LocationSetupScreen.tsx` (B1.5, B1.6):
  - English / Hindi language toggle
  - GPS permission request with locality fallback
- Build `src/screens/onboarding/HomeTerritoryRevealScreen.tsx` (B1.7):
  - Territory assignment card with Delhi H3 cell details, health index, animal mascot badge, and initial tasks preview

- Mobile app builds and bundles cleanly with `pnpm --filter @saafsafari/mobile typecheck` and Expo CLI.
- User can launch app, select Demo Citizen or Demo Collector, and immediately enter the authenticated app shell.
