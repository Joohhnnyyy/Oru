# Phase 6 Plan 03: Municipal Admin Console, Hotspot Heatmap, QR Registry Manager, Review Queue, and Amplify Hosting Build

**Phase:** 6 (Web Applications: Citizen Portal & Municipal Console)  
**Plan:** 03 of 03  
**Requirements:** `ADM-01`, `ADM-02`, `ADM-03`, `HOT-01`, `HOT-02`  
**Dependencies:** Plan 06-01 (Map & Auth Shell), Plan 06-02 (Citizen Features)

---

## 1. Goal

Build the Municipal Admin Console within `apps/web` for municipal authorities (`ward_admin`), including citywide health analytics, hotspot density visualization, QR source registration with printable QR exports, human-in-the-loop review queue resolution for AI photo proofs, and complete AWS Amplify Hosting build configuration.

---

## 2. Tasks & Implementation Steps

### Task 1: Municipal Admin Shell & Role Gate
- Build `src/components/admin/AdminLayout.tsx`:
  - Protects municipal views with client-side role check (`ward_admin`).
  - If a citizen visits, prompts with a 1-click "Switch to Ward Admin Persona" banner.
  - Admin header displaying active ward, authorization tier (Cedar Allowed), and quick navigation tabs:
    - **Territory Overview & Heatmap**
    - **QR Source Registry**
    - **AI Photo Review Queue**

### Task 2: Citywide Territory Health Overview & Hotspot Heatmap (`ADM-01`, `HOT-01`, `HOT-02`)
- Build `src/components/admin/TerritoryOverview.tsx`:
  - Fetches overview via `GET /v1/admin/territory-overview` against live API Gateway.
  - Metric summary cards:
    - **61 Total Territories**
    - **Average City Health** (e.g. 74%)
    - **Active Open Hotspots**
    - **Mood Distribution Bar** (Sick, Recovering, Thriving, Legendary counts).
  - High-density searchable territory table showing ward name, mascot, health score, and active hotspot count.
  - Quick action: "Report Hotspot" modal allowing admins or citizens to log a new dumping hotspot (`POST /v1/hotspots`) with instant 5-point territory health deduction and automated bounty assignment.

### Task 3: QR Source Registry & Printable QR Exporter (`ADM-02`)
- Build `src/components/admin/QrSourceManager.tsx`:
  - Fetches registered QR sources via `GET /v1/admin/qr-sources`.
  - Filterable table displaying QR ID, type (smart bin, collection truck, e-waste hub), ward location, geofence radius, and status.
  - **Register New QR Source Modal**:
    - Form accepting: Source Name, Type, Territory ID dropdown (61 Delhi wards), Latitude, Longitude, and Radius (meters).
    - Submits via `POST /v1/admin/qr-sources` live on AWS.
  - **Printable QR Code Voucher Dialog**:
    - Generates scannable QR code using `qrcode.react`.
    - Includes municipal header, official MCD crest styling, source ID, and installation instructions for field deployment.

### Task 4: AI Photo Verification Review Queue (`ADM-03`, `AI-03`)
- Build `src/components/admin/ReviewQueue.tsx`:
  - Fetches pending flagged submissions via `GET /v1/admin/review-queue`.
  - Queue cards displaying submission ID, user ID, territory ID, and timestamp.
  - **Review Detail Modal**:
    - Displays uploaded photo proof from S3 presigned URL.
    - Displays AI Evaluation report: Rekognition confidence tags, moderation flags, and Bedrock Nova Lite reasoning analysis.
    - Two decision buttons:
      - **Approve (Award Credits)**: Calls `POST /v1/admin/review-queue/resolve` with `approved: true` and awards Green Credits to citizen.
      - **Reject (Discard)**: Calls with `approved: false` and feedback message.
    - Completes the Step Functions task token callback live in AWS.

### Task 5: AWS Amplify Hosting Build Setup & Verification
- Create `amplify.yml` at repository root:
  - Configures frontend build for `apps/web`:
    - Base directory: `apps/web/dist`
    - Build commands: `pnpm install`, `pnpm --filter @saafsafari/shared build`, `pnpm --filter @saafsafari/game-rules build`, `pnpm --filter @saafsafari/web build`.
    - Cache paths: `node_modules/**/*`, `.pnpm-store/**/*`.
- Verify full production build succeeds with `pnpm --filter @saafsafari/web build`.

---

## 3. Verification Criteria

1. Elevating to `ward_admin` persona unlocks the Municipal Admin Console.
2. `GET /v1/admin/territory-overview` populates the 61-ward dashboard with average health and mood distributions.
3. Submitting the "Register QR Source" modal creates a new QR record in DynamoDB and displays a printable QR preview.
4. Review queue displays flagged submissions and approving/rejecting successfully calls `/v1/admin/review-queue/resolve`.
5. `pnpm --filter @saafsafari/web build` outputs a clean, production-ready static bundle in `apps/web/dist` with zero build errors.
